# Jev Mario：本地模型或官方 API

[English](./README.md)

真实 NES 模拟器 → SMB1 RAM / 结构化状态 → 本地
[`flock-io/this-that-model-1.2`](https://huggingface.co/flock-io/this-that-model-1.2)
→ 手柄。模型一次前向计算为九个动作打分，不生成文本。
默认仍使用这个完全本地的后端。显式选择 `jev-official` 后，可改用 TypeSafe 托管的
官方 Jev 决策模型，需要 API Key，并会发送结构化游戏状态。
两种模式都不发送截图或 ROM、不由脚本代选动作，也不包含 Nintendo 素材。

## 浏览器独立版与 Cloudflare

独立静态版已通过 Cloudflare Pages 发布到 **https://jev-mario.pages.dev**。
用户更正后的自定义域名为 **https://jev-mario.zoink.site**；
必须待 DNS 和证书激活后，才能认为该域名发布完成。
它不连接本地 Node 游戏，也不公开实时 Jev 接口；GitHub 仓库继续保持 PRIVATE。

访问者必须自行选择合法持有的 `.nes`。`File.arrayBuffer()` 仅把 ROM 读入当前
标签页内存；应用不上传、不调用模型、不使用账户、Cookie、分析追踪或 ROM 下载。
Cloudflare 会接收正常的站点请求，并可能保留基础设施日志；本地 ROM 不会发送给托管方。
正式回放要求与来源面板所列 SHA-256 完全相同的 Europe Rev A ROM；
其它受支持 SMB1 版本可用于手动游玩。JSNES 使用 NTSC 节拍，声音关闭。

- 回放从 1-1 开始，包括 **6275 个实际 Choice 与 486 条自动过场**，到第
  113645 帧、32 关全部完成时停止。支持暂停/继续、逐决策、1×/4×/16×；
  实际速度受设备性能限制。
- 展示实际保存的模型输入、问题、回答字段，不编造内部推理；未提供的概率、
  Score 不补造。
- 手动模式开启独立新局。先点击画面：方向键移动、Z/空格跳、X跑、Enter 为
  Start、右 Shift 为 Select。失焦、隐藏或离开页面时释放按键并暂停手动游戏。
- 每个回放边界核验物理状态，终态核验 framebuffer 的 SHA-256。
  3944 原 live 快照丢失及确定性重建限制仍明确显示；原局有维护和策略修改，
  不是新的无干预 AI 实验。

静态版构建只需要 Node 24+ 与 pnpm，不需要 Python 或模型环境：

```bash
pnpm install --frozen-lockfile
MARIO_REPLAY_LOG=midscene_run/logs/0e61deb0-42bd-4d6d-b554-87c6fa187020.jsonl pnpm build:static
pnpm preview:static
```

本地预览为 **http://127.0.0.1:4180**，不影响 4175 的冻结胜利态。
构建时需要本地私有的正式日志，单独克隆仓库不会得到日志。
日志缺失或被修改会明确报错，不会生成空回放充数。

`scripts/public-history.mjs` 核对源日志哈希后，仅导出固定白名单中的游戏字段、
问题及回答值。未知输入字段、非空 memory、敏感字符串或 Choice 不一致都阻止
构建。不会复制请求、头、密钥、账户元数据、原始日志、ROM、截图或 NES 快照。
53 个带哈希的 JSON 分块未压缩约 31 MB，浏览器只保留当前分块。
`scripts/build-static.mjs` 按显式文件清单生成被忽略的 `.cloudflare/site/`，
仅发布该目录；生成物及本机原始证据不提交到 Git。

源码；权限需覆盖本项目 Pages 发布及自定义域操作。DNS 编辑需要单独授权，
标准 Wrangler OAuth 登录不一定包含该权限。
发布前检查该账户已有的 `jev-mario` Pages 项目，以及精确的
`jev-mario.zoink.site` DNS/自定义域记录。若属于其它资源，先与所有者解决冲突，

## 两个分支

独立仓库从 `imink/midscene` 的 `examples/local-jev-mario` 提取：

- `gemma-baseline`：保存之前可运行的 Gemma + Jev 兼容适配器。
- `this-that-local`：本文档对应的原生本地决策模型。

切换分支前，先停止**从本仓库启动**的服务。原工作区和其 4174/8766/8765
服务独立保留，不需要停止。不会自动推送远端。

## 安装

需要 Node.js 24+、pnpm 9.3.0+、Python 3.12、uv，以及自己合法持有的
Super Mario Bros `.nes` 文件。Apple Silicon 使用 MLX float16，
模型权重约 3.76 GB，不进行量化。

```bash
cd ~/code/local-jev-mario
git switch this-that-local
pnpm install --frozen-lockfile
uv sync --frozen --python 3.12
pnpm download:model
```

依赖位于 `node_modules/` 和独立 `.venv/`；模型位于被 Git 忽略的
`models/this-that-model-1.2/`。只有安装阶段下载公开依赖和权重；
游戏期间只加载本地文件，并强制 Hugging Face / Transformers 离线。
不修改已有 Gemma 的 Python 环境。

若 `pnpm` 被 depot_tools 覆盖，可使用 `corepack pnpm` 或官方独立可执行文件。
Python 锁文件固定实际验证的依赖，MLX 版本采用本机已知兼容版本，
不会直接升级到尚未验证的新版本。

## 启动

终端一，在仓库目录启动模型：

```bash
pnpm model
```

看到 `Ready` 后，终端二：

```bash
curl http://127.0.0.1:8767/health
MARIO_ROM="/自己合法持有的游戏绝对路径/game.nes" pnpm start
```

打开 **http://127.0.0.1:4175**，点击「启动 Agent」。
也可以省略 `MARIO_ROM`，在页面选择并加载 `.nes`。ZIP 请先在本地解压。
页面上传的 ROM 仅在内存加载，不保存、不由 API 返回，也不传给模型。

仅在本开发机器上，用户提供的 ROM 已私下保存在被忽略的
`midscene_run/roms/user-supplied.nes`，可直接使用：

```bash
MARIO_ROM=midscene_run/roms/user-supplied.nes pnpm start
```

ROM 和模型权重都不进入 Git。缺少 ROM/权重、端口被占用、模型不可用或回答无效
都会明确报错。**没有 Gemma 回退**：保留的 `local-jev.mjs` 是旧适配器，
本分支的游戏会拒绝把其回答当成 This-That 决策。

## 官方 Jev API

### 观看历史回放

打开 **http://127.0.0.1:4175**，点击 **「回放本局（从 1-1 开始）」**，
即可在隔离的模拟器中离线播放当前已加载局。正式游戏必须已停止，
且没有在途或尚未完成记账的动作。可使用「暂停回放 / 继续回放」「下一决策」，
或输入已执行决策数后「定位并暂停」。`0` 表示开局画面。
逐步会完成当前决策及其自动过场；若已在决策边界，则推进一个决策。
支持 1×、4×、16× 速度，不计历史推理等待时间。
「返回正式游戏」只退出观战，不改变正式游戏。

画面与历史记录一起返回。显示的输入和问题属于该动作**执行前**的帧；
画面则展示这个动作的执行过程及随后游戏自身的过场。
可展开原始响应、Choice、概率、完整历史输入和当前回放 RAM。
缺失数据明确保留为缺失，不是模型内部推理文本，不编造推理。
失败或取消且未执行的请求不计为播放动作。重建的转移会保留来源提示，
包括已审计局日志索引 3944 丢失原 live 完整快照的限制。
该通关局包含维护暂停及局中策略修改，不是冻结策略的一次无干预实验。

回放不调用模型或 Agent，不写原始日志，不向浏览器传送 ROM。
服务只建立一次日志索引、按需读取当前记录、返回有界 PNG 画面，
最多保留 12 个定位检查点，不整份传输约 85 MB 日志。
每个服务同时只有一个回放会话；新标签页开启回放会使旧标签页的令牌失效。
退出回放前禁用正式游戏控制和服务检查；日志损坏或被修改会显式停止。
远距离定位需要重新推进历史帧，可能耗时约一分钟。
旧标签页若提示回放会话过期，请刷新页面后重新打开回放。

本机已审计局为 `0e61deb0-42bd-4d6d-b554-87c6fa187020`，
共 6275 决策、113645 帧、32/32、1 命。若服务已停止，可恢复其**终态**，
不创建新局、不追加或改写日志：

```bash
DECISION_BACKEND=jev-official TYPESAFE_ENV_FILE=.env USE_EXPERIENCE=0 \
MARIO_ROM=midscene_run/roms/user-supplied.nes \
RESTORE_TERMINAL_RUN=0e61deb0-42bd-4d6d-b554-87c6fa187020 pnpm start
```

端口已有服务时不要再开第二个服务。恢复时先在独立 NES 实例中逐转移校验，
然后才提供冻结终态；不请求推理、不启动 Agent。
本地必须已有私有 ROM 和历史日志，项目不分发它们。
这一终态恢复入口要求原局关闭跨局经验。
胜利画面停在游戏原生胜利触发帧，不另行推进结尾动画。

### 启用官方推理

官方模式不需要启动本地模型或安装 Python 环境。安装 Node 依赖后，
准备包含 `TYPESAFE_API_KEY` 的私有 `.env` 文件。文件只按数据解析，不执行或复制：

```bash
DECISION_BACKEND=jev-official \
TYPESAFE_ENV_FILE="/私有目录的绝对路径/.env" \
MARIO_ROM="/自己合法持有的游戏绝对路径/game.nes" pnpm start
```

也可通过进程环境提供 `TYPESAFE_API_KEY`。设置了 `TYPESAFE_ENV_FILE` 时，
优先使用该文件的密钥；文件或密钥缺失会明确报错。不要把密钥写进命令参数、源码或日志。
打开同一个 **http://127.0.0.1:4175** 页面，启动 Agent。
默认固定 `jev-1.14.0`；`JEV_MODEL` 可显式指定其他公开版本、`jev-latest` 或
`jev-preview`。别名会变化，每次决策记录服务实际返回的模型 ID。

密钥只通过服务器端 Bearer 请求头发送给
`https://api.typesafe.ai/v1/systemone` 或 `/v1/models`，禁止跟随重定向。
页面不会收到密钥；请求失败就停止 Agent，不重试、不投票、不换模型或替换动作。
本地模式仍只允许数字回环地址。切换后端需要重启服务器，页面不能更改端点或凭据。
非成功响应会在停止错误和 JSONL 日志中保留脱敏后的服务端错误类型、代码与说明。
诊断正文最多缓冲 4096 字节、读取 64 个流片段，读取与清理共用 2 秒期限；仅提取指定 JSON 字段、
纯文本或 HTML 标题，不保存原始响应头或其他对象字段。
先移除凭据和敏感字段行，再限制字段长度。正文过大、无法读取、格式错误或超时均有明确标记，
不编造原因、不重试请求，也不削弱原 HTTP 错误。此前已丢弃的正文不能因此补回。
官方请求使用 `Connection: close`，避免跨同步模拟预测保留连接池中的旧连接。
这只是隔离跨决策连接复用，不保证 API 始终可用，也不会自动重试失败请求。
`pnpm start` 将本进程的单地址连接尝试预算设为 2000 毫秒。
直接运行 Node 时使用
`node --network-family-autoselection-attempt-timeout=2000 server.mjs`。
这样后续 DNS 地址在 Node 24 保持不变的约 10 秒 fetch 连接总预算内仍有尝试机会；
若单地址也等待 10 秒，第一个地址就可能几乎耗尽总预算。
完整请求时限仍是 125 秒。地址切换发生在发送 HTTP 之前，不是重试决策请求。
DNS、官方域名、SNI 和证书校验保持不变，不固定服务 IP。
这只修正预算冲突，不保证解决所有网络故障，健康检查成功也不等于稳定性已获证明。

九个动作、结构化事实、预测预算和连续 32 关目标保持不变，一次请求同时包含 Choice 和 Noul。
官方 Choice `confidence` **不是**所选动作概率，页面分开显示，不伪造缺失值；
两者都不保证通关。官方概率会舍入到小数点后两位，合计可能为 0.99 而非 1。
仅当各选项的舍入区间允许合计为 1 时接受，保留原始数字和 Choice，不归一化，
也不放宽本地后端的校验。实跑还遇到官方 Choice 与概率最大项不一致的回答。
只要九选项分布有效且 Choice 属于声明的动作，仍以官方 Choice 为准，
在页面和日志明确警告，不代选最大项、不重试。格式错误仍停止 Agent，本地一致性校验保持严格。
从本地模型局面接续的运行属于混合后端证据，不算“纯官方 Jev 全通”。

同样的环境变量也可用于 `pnpm probe`（合成协议检查）或 `pnpm smoke`（独立短局 ROM 验证）。
这些检查不证明 32 关完成。官方 API 按 TypeSafe 的规则计费。
协议来源：[System One](https://docs.typesafe.ai/api/system-one)、
[模型](https://docs.typesafe.ai/models)、
[confidence](https://docs.typesafe.ai/confidence)。

## 动作和概率的含义

`local_this_that.py` 调用上游原版 `TypedDecider` 和 System One 协议解析器，
只是 HTTP 桥接层，不是另造一个模型。九个选项及其说明按声明顺序传入；
动作 Choice 和跳跃用途的二选一问题通过**一次前向计算**同时回答。

模型返回的原生索引直接对应 `noop`、`right`、`right_jump`、`right_run`、
`right_run_jump`、`jump`、`left`、`down`（下键进入水管）、
`left_jump`（同时按左和 A，向后跳过障碍）。
代码不会筛除、预选或替换任何动作。
页面展示经过校验的完整模型概率分布。此模型的 `confidence` 是
**所选动作的概率**，不是官方 Jev 的置信度定义，也不是马里奥通关率；
尚未在本游戏上做概率校准。Noul 是 `yes` 标签的概率，仅显示，不控制游戏。
没有请求危险度 Score。

使用原生分类 API 默认的温度 1.0，不是 Gemma 的文本采样温度。
生成 token 数确实为零；输入 token 数来自实际原生提示词构造器。
状态或提示词超过限制会明确报错，不悄悄截断。

每次决策前，隔离的模拟器副本为九个动作分别预测：下一决策间隔、
持续持有该动作 60 帧的结果，以及下一次能否重新起跳。
若当前间隔存活但持续持有会死亡，还会探索后续两个间隔的全部九种动作，
找到存活的延续就停止搜索（默认合计向前看 48 帧）。
没有任何延续存活时标为 `TRAP`。这是当前状态的物理事实，不是搜索程序替模型选动作。
没有 `TRAP` 标记不代表更远未来安全；预测副本不推进或回退真实游戏。
同一次同步预测内，完整且不变的 NES 快照复用 V8 编码字节，每次恢复仍解码出独立副本。
不省略 CPU、PPU、APU 或手柄字段，不减少候选动作或搜索预算；决策结束即丢弃缓存。
预测还会在四个搜索间隔内，寻找能存活到“已落地且 A 已松开”的决策边界，
或进入游戏自动过场的延续，最多允许一次后续按键组合变化。
首间隔等于实际控制时长，后续搜索间隔取不小于 16 帧的最小控制间隔整数倍；
因此 4、8、16 帧控制分别保留 52、56、64 个物理帧的准备边界观察范围。
窗口内每个真实控制边界都会检查准备状态，包括首动作终点，而不只检查较长搜索间隔的端点。
缩短控制间隔不应漏掉原先见证路径在这些端点之间经过的落地窗口。
`survivesWithOneReplan` 只记录是否找到这种延续，不返回要执行的后续动作。
没有找到不等于已证明陷阱。这避免把“尚未死但已无救的下落”，
或“落地时仍按住 A、不能再次起跳”，误当成有用的下一决策状态。
如果持续按键最终死亡，不能仅凭站稳或松开 A 就判定有存活证据；
初始和后续准备边界都使用相同的存活验证：遍历九个动作、检查两个较长间隔，
较早的边界检查三个间隔，避免因边界提前而缩短物理证据范围。
延迟松 A 也按真实控制边界采样：最多 `1 + 2 * continuationFrames / frames` 个松键时点、
九个后续动作，每支仍限制在三个较长后续间隔的物理窗口内。
这些有限预算只证明有界见证，不保证无限存活；检查后恢复候选副本，不改变真实游戏。
这一次未来换键也可延后：在继续原跳跃最多两个较长间隔内松 A。

所有按键选项仍保留。
延续证据还须伴随一个身体尺度的移动或新恢复的起跳准备，不能因为未来有出路就一直原地等待。
其他楼层只是待验证的可能路线：模型可以完成一次仍会回绕的落地尝试，下一次再排除实际失败的楼层；
空中回绕与站稳后验证楼层仍分开处理。
沿已观察到的迷宫备选路线行进时，若存活延续有区别，可优先询问带有这种证据的向前一步，
而非反复退离可以松键再跳的坑边；向后选项仍保留，不替换模型选择。

当动作预测在立即存活/已检测陷阱上存在区别时，请求会聚焦这一布尔事实，
暂时不混入前进距离的竞争目标。持续持有 60 帧的结果只是警告，不是必须满足的条件：
模型下个间隔可以改变动作。把危险的长按一律当成危险的即时动作，
曾导致真实模型在 1-2 坑前反复徘徊。包括危险动作在内的九个选项仍全部列出，
程序不排序、移除或替换模型选择。这是规则引导的模型控制，
不是宣称模型独立学会了完整游戏策略。聚焦问题已改善真实本地模型对照中的错误选择，
但仍不保证每次安全。
如果存在带有足够位移的上述延续，其证据优先于较弱的存活信号；
已证明的陷阱仍会使这种延续不合格。
位移必须来自实际首间隔或尚能存活的长按路径，不能只借用死亡长按路径的大位移，
从而挤掉真正重新获得控制能力的短距离落地。
仅当没有上述移动存活证据时，从不能起跳/划水变为重新准备就绪的下一边界
才可成为后备焦点，即使位移不足一个身宽。
短距离落地能恢复控制能力，不必先移动 16 像素；但不与已有的移动证据并列，也不替代它。
已经准备就绪的静止状态没有这项例外，且仍须存在可用的延续证据。
若短间隔预测范围内所有动作都没有可用的准备边界证据，
但已有的 60 帧长按结果存在存活差异，则聚焦长按存活且没有已检测陷阱这一事实，
避免弹簧板的短间隔丢弃已有的减速证据。
这不会在已有重新规划证据时强求长按安全，也不增加模拟预算或执行假设的长按。
模型输入分别标明首动作、准备边界搜索和长按预测的实际帧范围；
没有找到准备证据明确表示有界搜索下未知，不等于已经证明无法存活。
没有混合安全风险时，进入预测到的水管/区域，或移动到已知阻塞点之外，
也可以成为单独的问题焦点。导航要求下一间隔或长按终点至少移动一个身宽（16 像素）
或一个身高，避免把微小惯性漂移误认为脱困，也不因继续长按 A 会沉回去而忽略有效的上划。
水下新启动且实际向上移动的划水也算有效移动，不要求短间隔内达到整个身高。
松 A 或等待到可以再次起跳/划水、且仍在移动的短间隔也可以有效：
分别检查下一间隔和长按终点，不因一直长按会回到阻塞点，就否定松键后再规划的可能性。
如果所有动作都满足导航条件，就保留完整结果表，不用全为真的问题抹掉前进效果的差别。
水下向前长按若预测下落/死亡且脚部到达或超过 240 像素画面底边，
可在普通前进目标之前聚焦存活的上升动作，提前警告深坑和下拉水流。
这不是要求每个动作都能安全地一直长按。
原来的八个动作全部保留；
`left_jump` 只是补上缺失的手柄组合，不是自动执行的脱困步骤。
更深的危险前瞻可能让单次决策增加数秒；没有相应危险的普通状态会跳过这部分搜索。

## 游戏行为

- 通过正常 START 流程从 1-1 开始，不修改 RAM，不注入存档。
- 支持原版 mapper-0 iNES SMB1：32 KiB PRG、8 KiB CHR、无 trainer，
  共 40976 字节。遥测采用 World 布局，用户的 Europe Rev A 已运行过；
  仅凭文件头不能识别其他游戏或改版。
- **JSNES 使用 NTSC 时钟，欧洲版是兼容运行，不是精确的 50 Hz PAL 模拟。**
  页面显示本地 NES framebuffer，无声音。
- 常规默认每 16 个模拟帧决策一次，水下或非静态地板支撑时最多 8 帧、弹簧板附近最多 4 帧，不是每秒推理 16 次。推理期间游戏暂停。
  落地后继续按住 A 不能重新起跳，必须由模型选择不含 A 的动作松键。
- 目标是 **从 1-1 到 8-4 全部 32 关，不跳关**。普通旗杆和前面世界的城堡
  只算中间关卡完成，不再结束整场游戏。页面和模型都能看到当前关卡及已完成关卡。
- 游戏接管控制的演出和载入阶段松开所有按键，正常推进 NES 帧，恢复可操控后
  再由模型选择动作。这些帧单独记录为 `automatic-transition`，不冒充模型决策，
  不修改 RAM 或跳过计时器；连续切换超过 6000 帧会明确报错。
  换关/换区域会清理失效的速度和地形历史。
- 只有到达 8-4 城堡胜利状态，且**本局已记录全部 32 关完成**，才算整场通关。
  跳关后到达 8-4 会报告目标未完成，不伪报成功。
- **默认开启连续模式**：死亡后正常推进游戏自身的死亡/复活动画，消耗一条生命，
  然后由模型从游戏规定的出生点/检查点继续。本局已完成关卡保留。
  生命耗尽后通过正常启动和 START 流程开始新局，生成新 run ID，
  已完成关卡归零，不把不同局的进度合并。不会修改生命数、检查点或计时器。
  `CONTINUOUS_PLAY=0` 可恢复死亡即停止的旧行为。
- 手动暂停始终有效，包括复活期间。服务错误和安全上限仍会明确停止；
  连续模式不会吞掉错误，也不保证模型最终能解出所有关卡。
  暂停会取消请求并丢弃迟到回答。
- **默认关闭跨局经验**：不读取、不保存之前的局数。只有 `USE_EXPERIENCE=1`
  才显式启用有界事实记忆，不是权重训练；否则已有历史不变。

| `MAX_DECISIONS` | `20000`，整场游戏共用 |

| `USE_EXPERIENCE` | `0` |

更改模型端口：`pnpm model --port 8768`，游戏端对应设置
`THIS_THAT_BASE_URL=http://127.0.0.1:8768`。
两个服务都仅绑定 `127.0.0.1`，校验 Host/Origin 并拒绝跨站请求。
本地模型地址仅允许数字 HTTP 回环地址；禁止重定向、DNS 域名和 URL 内凭据。
显式启用官方模式后，仅允许固定的 TypeSafe HTTPS API，仍禁止重定向。

`midscene_run/logs/<run-id>.jsonl` 保存完整遥测、实际精简输入和问题说明、
模型身份/原生分布、执行动作、后续坐标及错误。所有运行产物均被 Git 忽略。
模型失败会停止游戏，不会变成默认动作。
模拟器推进后、遥测采样前，立即用 `applied` 或 `automatic-applied`
记录实际动作、帧范围及原始 2 KiB RAM。采样或后续 transition 写入失败时，
状态会保留 `pendingApplied`，错误标记为 `post-action`；缓存遥测此时可能仍对应上一帧边界。
已执行的模型决策仍计数，不得重新请求该 Choice，也不得在恢复时忽略已执行的帧。

```bash
pnpm run lint
pnpm test
pnpm run test:python
pnpm probe
MARIO_ROM=midscene_run/roms/user-supplied.nes SMOKE_DECISIONS=20 pnpm smoke
```

单元测试不需要模型权重或 Nintendo ROM，包含在真实 JSNES 中执行的原创极小 6502 程序。
`probe` 用合成 RAM 测试真实模型；`smoke` 才使用用户 ROM 和真实模型。
mock 通过或短程 smoke 都不等同于通关。
